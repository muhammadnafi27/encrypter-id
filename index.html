🔐 Mengapa AES-GCM Aman?

AES (Advanced Encryption Standard) dengan mode GCM menggunakan kunci 256-bit, memberikan 2²⁵⁶ kemungkinan kunci. Bahkan superkomputer tercepat di dunia membutuhkan waktu lebih lama dari usia alam semesta untuk mencoba semua kunci. GCM juga menyediakan authentication, memastikan data tidak diubah selama transfer.

🔑 Mengapa RSA-OAEP Aman?

RSA dengan kunci 2048-bit mengandalkan kesulitan memfaktorkan bilangan prima besar. Tidak ada algoritma yang diketahui dapat memfaktorkan angka sebesar ini dalam waktu yang wajar. OAEP padding mencegah serangan chosen-ciphertext. RSA digunakan oleh bank, pemerintah, dan infrastruktur internet di seluruh dunia.

Alur Kerja Detail
1

User Upload File

Pengirim (Alice) memilih file yang ingin dikirim melalui drag-and-drop atau file browser. File dibaca ke dalam memory browser sebagai ArrayBuffer.

2

Sistem Membuat AES Key

Sistem men-generate kunci simetris AES-GCM 256-bit menggunakan Web Crypto API (window.crypto.subtle.generateKey). Kunci ini bersifat random dan unik untuk setiap sesi enkripsi.

3

File Dienkripsi dengan AES-GCM

File data dienkripsi menggunakan AES-GCM dengan kunci AES yang baru dibuat. Proses ini menghasilkan ciphertext dan Initialization Vector (IV/nonce) 96-bit yang unik. GCM mode juga menghasilkan authentication tag untuk memverifikasi integritas data.

4

AES Key Dienkripsi dengan RSA Public Key Penerima

Kunci AES (32 bytes) dienkripsi menggunakan RSA-OAEP dengan public key milik penerima (Bob). Hanya private key Bob yang dapat membuka kunci ini. RSA menggunakan panjang kunci 2048-bit.

5

File Terenkripsi + Encrypted AES Key Dikirim

Ciphertext, IV, encrypted AES key, dan metadata dikemas menjadi satu package JSON. Package ini dikirim ke penerima. Penyadap yang mendapatkan package ini tidak bisa membacanya tanpa private key Bob.

6

Penerima Membuka AES Key dengan RSA Private Key

Bob menggunakan RSA private key-nya untuk mendekripsi encrypted AES key. Proses ini menggunakan RSA-OAEP decryption. Hanya private key yang cocok dengan public key yang dipakai untuk enkripsi yang bisa berhasil.

7

AES Key Dipakai untuk Dekripsi File

Kunci AES yang sudah didekripsi digunakan bersama IV untuk mendekripsi ciphertext menjadi file asli. GCM authentication tag memastikan file tidak diubah selama pengiriman. File asli dapat didownload.

AES-GCM (Symmetric)

  • Advanced Encryption Standard - Galois/Counter Mode
  • Panjang kunci: 256-bit (AES-256)
  • IV (Initialization Vector): 96-bit (12 bytes)
  • Menyediakan enkripsi DAN autentikasi (AEAD)
  • Digunakan untuk mengenkripsi file data (bulk encryption)
  • Sangat cepat - hardware-accelerated di CPU modern
  • Standard NIST, digunakan di TLS, HTTPS, VPN

RSA-OAEP (Asymmetric)

  • Rivest-Shamir-Adleman - Optimal Asymmetric Encryption Padding
  • Panjang kunci: 2048-bit
  • Hash function: SHA-256
  • Public key untuk enkripsi, Private key untuk dekripsi
  • Digunakan untuk mengenkripsi kunci AES (key exchange)
  • Aman selama faktorisasi prima besar tetap sulit
  • OAEP padding mencegah serangan chosen-ciphertext
Security Considerations
  • › Semua proses kriptografi berjalan 100% di browser menggunakan Web Crypto API - tidak ada data yang dikirim ke server.
  • › Private key harus dijaga kerahasiaannya. Jangan membagikan private key kepada siapapun.
  • › IV (Initialization Vector) selalu di-generate secara random untuk setiap enkripsi untuk mencegah serangan replay.
  • › GCM authentication tag memverifikasi integritas data - file yang dimodifikasi akan gagal didekripsi.
  • › Brute force simulator hanya untuk demonstrasi edukatif menggunakan dummy key kecil (8-16 bit). Tidak ada serangan terhadap sistem kriptografi asli.
